# 第一章：前端工程化导论

## 1. 什么是前端工程化

前端工程化是指将**软件工程的思想和方法**应用到前端开发中，通过工具、流程和规范来提升开发效率、保证代码质量、简化协作流程。

简单来说，前端工程化回答了一个核心问题：

> 如何让前端开发从"写页面"变成"做工程"？

早期的前端开发可能就是一个 HTML 文件加一个 CSS 文件，但现代前端应用动辄数十万行代码，涉及多人协作、复杂构建、持续交付。没有工程化，这些工作几乎无法高效完成。

---

## 2. 前端工程化解决的问题

### 2.1 协作问题

- 多人同时开发，代码冲突如何解决？
- 代码风格不统一，如何保证一致性？
- 模块划分不清晰，如何降低耦合？

### 2.2 效率问题

- 修改一行代码，如何快速看到效果？
- 开发环境和生产环境的差异如何弥合？
- 重复的样板代码如何自动生成？

### 2.3 质量问题

- 如何在编码阶段就发现潜在 bug？
- 如何保证每个功能都经过测试？
- 如何进行代码审查（Code Review）？

### 2.4 部署问题

- 如何从代码提交到上线全流程自动化？
- 如何实现灰度发布、回滚等运维能力？
- 如何优化资源加载速度？

## 4. 核心工具概览

### 4.1 包管理器

| 工具 | 特点 | 适用场景 |
|------|------|----------|
| **npm** | Node.js 默认包管理器，生态最大 | 通用场景 |
| **yarn** | Facebook 出品，注重速度和确定性 | 中大型项目 |
| **pnpm** | 硬链接 + 符号链接，节省磁盘 | Monorepo 项目 |

### 4.2 构建工具

| 工具 | 特点 | 适用场景 |
|------|------|----------|
| **Vite** | 基于 ESBuild，开发极速启动 | 现代项目首选 |
| **Webpack** | 功能最全，插件生态丰富 | 复杂项目 |
| **Rollup** | 打包体积小，Tree-shaking 优秀 | 库开发 |
| **esbuild** | Go 编写，速度极快 | 底层工具 |

### 4.3 前端框架

| 框架 | 特点 | 适用场景 |
|------|------|----------|
| **Vue 3** | 渐进式，易上手，中文生态好 | 中小项目 |
| **React** | 社区最大，灵活度高 | 各类项目 |
| **Angular** | 企业级，功能完整 | 大型企业应用 |

### 4.4 代码质量工具

| 工具 | 作用 | 说明 |
|------|------|------|
| **ESLint** | 代码检查 | 发现潜在问题和不规范代码 |
| **Prettier** | 代码格式化 | 统一代码风格 |
| **TypeScript** | 类型系统 | 编译时类型检查 |
| **Husky** | Git Hook | 提交前自动检查 |
| **lint-staged** | 增量检查 | 只检查暂存区文件 |

### 4.5 测试工具

| 工具 | 类型 | 说明 |
|------|------|------|
| **Vitest** | 单元测试 | Vite 原生支持 |
| **Jest** | 单元测试 | 最流行的测试框架 |
| **Cypress** | E2E 测试 | 端到端测试 |
| **Playwright** | E2E 测试 | 微软出品，多浏览器支持 |

## 6. 总结

前端工程化不是某一个工具，而是一套**完整的开发体系**。它涵盖了从编码到部署的全流程，目标是：

1. **提高效率**：自动化重复工作，减少手动操作
2. **保证质量**：通过规范和检查，减少人为错误
3. **便于协作**：统一标准，降低沟通成本
4. **持续交付**：从代码到上线，全流程自动化
